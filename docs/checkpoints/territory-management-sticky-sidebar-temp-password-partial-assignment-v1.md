## Design decisions confirmed via `AskUserQuestion` before implementing
- Temp password delivery: shown to the Admin in the UI after inviting/resetting, for them to relay directly — no new email infrastructure.
- Forgot-password unification: both invite and reset now avoid emailed magic links for Group Leader accounts entirely, eliminating that whole fragility class rather than continuing to debug it link-by-link.

## Summary of Changes
- **Item 3's redesign matters beyond the literal example given.** The old hard block used `partnershipCount > maxPossiblePartnerships` as an error condition; the fix simply clamps `actualPartnershipCount = Math.min(partnershipCount, maxPossiblePartnerships)` and lets generation proceed — `assignment_batches.requested_partnership_count` already stored the original ask separately from actual partnership rows created, so the shortfall (and the note built from it) needed no new schema, just reading data that was already there.
- **Item 5/6 fixes the deeper cause, not just the invite link.** The temp-password approach for Group Leaders sidesteps the entire PKCE-vs-implicit-flow class of bugs diagnosed in the prior session's checkpoint (`territory-management-invite-flow-map-recovery-field-rename-v1.md`) — there's no link at all to expire or mismatch. For the Admin's own forgot-password (`?code=...`, a different URL shape than the invite's `#access_token=...`), added a parallel manual-exchange fallback using the confirmed-real `supabase.auth.exchangeCodeForSession()` API, since the existing auto-detection depends on a `code_verifier` cookie surviving the round trip and there was previously no fallback if it didn't.
- `profiles` RLS/grants (migration 015) revoke all `insert`/`update` from the `authenticated` role — confirmed via the earlier research pass that even a user clearing their *own* `must_change_password` flag needs the service-role client, which `changePasswordAction` does.
- `useServerAction`'s generic conversion needed a `Awaited<T>` cast internally — TypeScript can't structurally reduce `Awaited<T>` for a still-abstract generic bound only by `extends ActionResult`, even though every concrete `T` used here is a plain object where `Awaited<T>` and `T` are identical. Backward-compatible; every pre-existing caller still infers `T = ActionResult` unchanged.
- `npx tsc --noEmit` clean, `npx vitest run` 52/52 passing, `npx next build` clean across all routes (one build-time fix needed: `change-password/page.tsx` required `export const dynamic = 'force-dynamic'`, same as every other TMS page touching Supabase server-side, since it would otherwise try to statically prerender at build time without live env vars).
- **Live-verified in the browser** via a scratch route (removed before commit) rendering `DashboardSidebar`, `AssignmentForm`, `GroupLeadersManager`, and `ChangePasswordForm` directly with mock data: confirmed the sidebar stays visually pinned in place while 1400px of filler content scrolls past underneath it; confirmed the territory checklist shows "M-11 — Sample Barangay" / "Q-9 — Another Barangay"; confirmed a Group Leader entry created *today* (would have failed the old 6-month gate) now has an enabled Delete button; confirmed the Reset Password button and ChangePasswordForm render correctly.
