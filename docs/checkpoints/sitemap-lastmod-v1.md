# Sitemap lastmod — v1

**Date:** 2026-08-18
**Product:** Site-wide (next-sitemap generation)
**Feature:** Replace build/generation-timestamp lastmod with genuine per-route modification dates

## Files Modified
- `next-sitemap.config.js` — `transform()` now calls `getLastmod(path)` instead of `new Date().toISOString()`.
- `src/lib/sitemap/lastmod.js` (new) — reads the committed `lastmod-map.json`, returns `undefined` (never a fabricated date) for any route with no genuine source.
- `src/lib/sitemap/lastmod-map.json` (new, committed data) — `{ route: ISO-8601 date }` for all 232 routes, generated by the script below.
- `scripts/generate-sitemap-lastmod.js` (new) — the maintenance script that (re)builds `lastmod-map.json` from real sources (blog frontmatter, portfolio JSON dates, git history of per-route source files). Run manually whenever content changes; not part of the Vercel build (see rationale in the script's header comment — Vercel does a shallow git clone, so `git log` at build time would collapse back to a uniform date).
- `src/lib/sitemap/__tests__/lastmod.test.ts` (new) — 8 tests, incl. regression guards against the original bug.
- `package.json` — added `"sitemap:lastmod": "node scripts/generate-sitemap-lastmod.js"`.
- `public/sitemap-0.xml` — regenerated with real per-route dates (232 URLs unchanged, 48 distinct truthful `lastmod` values instead of 1 uniform build timestamp).

## Source used per category
- **Blog posts** (`/blog/<slug>`) — the post's own `date:` frontmatter field in `src/content/blog/<slug>.md`. Author-declared, most authoritative source available (6 routes).
- **Portfolio case studies** (`/portfolio/<slug>`) — the case study's own `"date"` field in `src/data/portfolio/<slug>.json` (5 routes).
- **Career blueprints** (`/careers/<slug>`) — no date field exists in that data model, so: git's last-commit date for that specific blueprint's own JSON file (`src/data/careers/<slug>.json`) — a real, non-fabricated signal of when that blueprint's content last changed (15 routes).
- **Services** (`/services/<slug>`) — same reasoning as careers: git last-commit date of `src/data/services/<slug>.json` (6 routes). **Architecture note surfaced by this task:** the Supabase `services` table does have a genuine `updated_at` column, but the live `/services/[slug]` pages are statically rendered from these JSON files, not from the database (`src/lib/services/data.ts` imports the JSON directly) — so the JSON file's own history is what's actually materially true of the rendered page today. If that data source is ever switched to read live from Supabase, this rule should switch to the DB `updated_at` value instead.
- **Tool alias pages** (`/tools/<slug>` for the dynamic-route entries only — `ai-confidence-analyzer`, `computer-skills-analyzer`, `digital-literacy-checker`) — git last-commit date of the shared `src/lib/tools-data.ts` (all tool metadata lives in one file, so this is coarser than the per-item cases above, but still genuine, not fabricated) (3 routes).
- **Everything else** (197 routes — home, hub pages, static marketing pages, every `/learn/**` lesson, guides, demo pages, etc.) — git's last-commit date of that route's own `src/app/<route>/page.tsx` source file.

Nothing uses `new Date()`, build time, deployment time, or request time anywhere in this chain.

## URLs with lastmod omitted
None. All 232 current routes resolved to a genuine date (6 from frontmatter, 5 from JSON date fields, 221 from git history). If a future route's source file is ever untracked/uncommitted when the script runs, it is omitted from the map on purpose — `getLastmod()` returns `undefined` and next-sitemap drops `<lastmod>` for that URL entirely rather than inventing one.

## Test / build results
- `npm test` — **15/15 passing** (7 existing exclusion tests + 8 new lastmod tests, including: no-fabrication guard for unknown routes, frontmatter/JSON exact-match checks, and two regression guards — distinct-value-count check and a "not uniformly stamped as now" check that would fail if a future change reintroduced build/request-time stamping).
- `npx tsc --noEmit` — clean, no type errors.
- `npx next-sitemap` (regenerate against the existing `.next` build manifest) — 232 URLs, unchanged from before this fix, 48 distinct real `lastmod` values, zero uniform timestamps.
- **Full `npm run build` could not be completed in this sandbox** — Turbopack's font-loading step needs to fetch `Inter`/`Syne` from `fonts.googleapis.com`, and this sandbox's outbound network is allowlisted and does not include that host (confirmed: a separate fetch tool *can* reach it, but the Node build process inside the sandboxed shell cannot — a pre-existing environment constraint unrelated to this change, not something this fix touches). This is the same limitation that applied to the previous sitemap-exclusion fix in this repo. Real build verification will happen on Vercel's CI, which has full internet access, exactly as it did for the previous fix.
