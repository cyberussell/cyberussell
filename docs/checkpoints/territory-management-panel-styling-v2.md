## Summary of Changes
- v1's `#E2E8F2`/black-border decision was based on Russell's own confirmed answer at the time ("panels themselves"), but seeing it live on a real record detail screen showed the opposite reads better — panels staying white/light with the page darkened around them makes the panels pop rather than blend into a uniformly dark product. Corrected without re-litigating — this was concrete visual feedback on a shipped result, not a new ambiguity to negotiate.
- The "affected texts" contrast work from v1 (bumping text sitting on the darkened *panel*) is still valid and was left alone — panels are white again, so slightly darker slate tones there are harmless, just no longer strictly required. The *new* contrast work this pass is for text sitting directly on the newly-darkened *page* background, which is a different, non-overlapping set of text (page-level captions/subtitles vs. panel-level hints), found by tracing exactly which text sits inside a `bg-white`-backed panel/header/footer (unaffected) vs. directly against the page's own background (needed a bump).
- `#C9D8EE` chosen the same way `#E2E8F2` was in v1 — a hex literal in the same family as the existing palette (`#F3F8FF`, `#F8FBFF`), clearly darker than the old near-white page background, but still light enough that white panels read as "elevated" rather than washed out.
- The glow effect is a second `box-shadow` layer (`0_0_18px_-3px_rgba(148,163,184,0.6)`, a soft slate-toned blur with a negative spread so it reads as a halo rather than a hard outline) layered alongside each panel's existing drop shadow — applied everywhere `border-2 border-black bg-[#E2E8F2]` was in v1, so the treatment is consistent across the same ~35 panel locations.
- Ordinal header: reused `assigned.sequence` (already fetched on `PartnershipRecordDetail`, the same field `AssignedRecordsList` already numbers records with — "1. Address" — so no new data plumbing was needed). `ordinal()` handles the standard English suffix rules including the 11th/12th/13th exception. Anton is loaded scoped to this one component (not merged into the sitewide Syne/Inter faces in root `layout.tsx`), since it's a one-off display label, not running text. Font color kept at the existing dark-navy `#0B1B33` used for every other heading sitewide — a safe, already-proven-legible choice across all four of this card's tone variants (white/red-50/emerald-50/amber-50 — all light backgrounds), satisfying "contrast to the background" without needing per-tone color logic.
- `npx tsc --noEmit` and `npx next build` both clean, zero errors/warnings.
- Live-verified in the browser preview: `/territory-management-system/login` and `/territory-management-system/forgot-password` both show the darker page background with a white, glow-bordered panel floating on top, exactly matching the screenshot feedback. Zero console errors on both.
