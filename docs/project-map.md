## 9. Territory Management System (TMS) — Supabase live, actively being verified in production

**Purpose:** Standalone multi-congregation SaaS for organizing, assigning, and tracking territory work during field ministry — architecturally modeled on the Appointment System/LMS: own Supabase project, own auth, own middleware-free page-level auth gating, own lib/component namespace, fully isolated from Cyberussell.com and the other products. Covers the tenant foundation (congregations), the full Administrator module (territories/sections/blocks, records, CSV import/export), an assignment engine with a QR-based publisher workflow (offline-capable, IndexedDB-backed sync), a Group Leader role/dashboard (assignment generation, tabbed stats/results/partner views), Admin-driven Group Leader account invites/history, and a `/tms` short-URL redirect.

**Status as of 2026-07-13:** Supabase project provisioned and live; the product is mid-way through its first real live-data verification pass, one feature/bug at a time as Russell clicks through it. Several real bugs found and fixed on real screens as they were first exercised (see checkpoint list below) — a running theme is that this whole product was previously only code-audited, never click-tested, so more may surface. Assignment generation and oversight are now exclusively the Group Leader's domain — the Admin's read-only Assignments pages were removed outright. See checkpoints `territory-management-foundation-v1.md` (original build), `territory-management-production-audit-v1.md` (code audit), `territory-management-group-leader-login-fix-v1.md` (first live bugs), `territory-management-publisher-workflow-v2.md` (claim-on-name, read-only browsing, sync/thank-you flow, early termination, "Other" result), and `territory-management-group-leader-invites-v1.md` (Group Leader invite/history system + GL dashboard nav rework).

**Main routes:**
- `/tms` — short-URL redirect to `/territory-management-system/login`; `/tms/*` redirects to the equivalent long path
- `/territory-management-system/login` (Admin + Group Leader shared login; no public signup, provisioning is invite-only for Group Leaders, manual for the first Admin) + `/forgot-password`, `/set-password` (shared by password reset and Group Leader invite acceptance — both land here via the same Supabase `PASSWORD_RECOVERY` event)
- `/territory-management-system/dashboard` (+ `/territories`, `/territories/new`, `/territories/[territoryId]`, `/records`, `/records/[recordId]`, `/group-leaders`, `/reports`, `/settings`) — Administrator role
- `/territory-management-system/group-leader/dashboard` — Group Leader role; a Home/Dashboard/Visit Results/Ministry Partner tab bar under the congregation header (Home holds the QR code + assignment generate/regenerate/delete)
- `/territory-management-system/assignment/[batchToken]` (+ `/progress`, `/[partnershipToken]`) — public, unauthenticated, QR-scanned publisher routes; the opaque token is the only credential. Publisher workspace: claiming happens when a Ministry Partner saves their name (not merely by opening the link), a device is bound to one partnership per batch (others open read-only), and finishing all assigned records leads to a Sync screen then a "Thank you for your service today!" screen. An "End My Ministry Early" action marks unfinished records with a real `undone` visit result.

**Main page entry files:**
- `src/app/territory-management-system/login/page.tsx`, `.../forgot-password/page.tsx`, `.../set-password/page.tsx`
- `src/app/territory-management-system/dashboard/layout.tsx`, `.../dashboard/page.tsx`, and one `page.tsx` per dashboard sub-route listed above (including `.../group-leaders/page.tsx`)
- `src/app/territory-management-system/group-leader/dashboard/layout.tsx`, `.../page.tsx`
- `src/app/territory-management-system/assignment/[batchToken]/page.tsx`, `.../progress/page.tsx`, `.../[partnershipToken]/page.tsx`
- `src/app/territory-management-system/actions/{auth,territories,records,congregation,assignments,publisher,group-leaders,password,shared}.ts` — Server Actions used for all mutations (admin actions run session-scoped/RLS-enforced; publisher actions and the Group Leader-management actions run on the service-role client — the former because there's no RLS to fall back on for an unauthenticated public path, the latter because `profiles` RLS was never given a "read other congregation members" policy — both independently re-verify congregation/token ownership of every referenced id rather than trusting the client)

- `002_assignment_engine.sql`: `assignment_batches`, `assignment_batch_territories`, `partnerships`, `partnership_records` — the QR/token-based publisher assignment schema (128-bit opaque tokens, no RLS for the public path by design — enforced in application code instead). Also widens the visit-result set and adds `plus_code` to records.
- `003_group_leader_and_reports.sql`: adds the `group_leader` profile role + read-only RLS policies across every table.
- `004_group_leader_assignment_management.sql`: moves assignment-batch write access from Admin to Group Leader.
- `005_publisher_workflow_v2.sql`: widens `territory_record_visits.result` for `'other'`/`'undone'`, adds `partnerships.ended_early_at`.
- `006_group_leader_management.sql`: adds `profiles.email` (denormalized) and `profiles.revoked_at`.

**Library files** (`src/lib/territory-management-system/`): `supabase.ts`, `supabase-server.ts`, `hooks/useServerAction.ts`, `modules/{auth,congregation,territory,records,dashboard,assignment,reports,offline,groupLeaders}/*`. `assignment/engine.ts` is a pure, DB-free sequential-assignment calculator; `assignment/qr.ts` generates the batch QR code; `offline/{db,queue,sync,download,useOnlineStatus,claim}.ts` is the IndexedDB/localStorage-backed offline layer for the publisher workspace (`idb` dependency) — `claim.ts` is a device-local (not DB) record of which partnership a given browser is bound to for the current batch.

**Major dependencies:** `@supabase/supabase-js`, `@supabase/ssr`, `zod`, `papaparse` (CSV import), `qrcode` (assignment QR codes), `idb` (offline IndexedDB wrapper), `lucide-react`, `sonner`.

## Notes / caveats

- This map reflects the codebase as read on 2026-07-07. Re-verify file paths before relying on this for a refactor — routes and components move.
- **Mission Control** (`/mission-control/*`) is the shared admin CMS behind Learn (blueprints, pillars) and Services (service catalog, client intake) — it is not one of the 7 public-facing products but is referenced throughout since it owns their content.
- The Appointment System is architecturally isolated from the rest of the site: separate Supabase project, separate auth, mostly Server Actions instead of API routes, and its own component/lib namespaces — consistent with it being extraction-ready as a standalone SaaS.
